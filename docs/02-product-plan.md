# プロダクト企画

## 想定ユーザー

主なユーザーは、現場作業をしながら報告書、日報、経費、請求を管理する人。

初心者でも迷わないように、専門用語よりも日常の業務の言葉を優先する。

## コア価値

「現場で入力した内容が、報告書・日報・請求までつながる」こと。

同じ情報を何度も打たない。
PDFや請求の作成でミスを減らす。
過去の現場や請求を探しやすくする。

## 最初に作るべき機能

### 1. ホーム

今日やること、最近の報告書、今月の請求状況を見られる画面。

### 2. 完了報告書

- 新規作成
- 下書き保存
- PDF作成状態の確認
- 過去報告書の検索
- PDFリンク表示

### 3. 日報・作業金

- 作業日
- 作業金
- 残業代
- 駐車場代
- 高速代
- 備考
- 月次請求への紐づけ

### 4. 経費・溶剤

- 溶剤選択
- 数量
- 単価
- 小計
- 請求から引く項目の管理

### 5. 月次まとめ

- 月ごとの合計
- 請求書PDF
- 月次作業金一覧PDF
- 下書き、確認済み、発行済みなどの状態

### 6. 設定

- 作業者名
- 請求先
- 溶剤マスタ
- 単価
- Drive保存先

## 既存から引き継ぐ候補

- Google Sheetsの項目名と既存データ
- 完了報告書の台紙
- 請求書テンプレート
- 月次作業金一覧テンプレート
- PDFの命名ルール
- Driveの保存先フォルダ
- 溶剤マスタ

## リニューアルで改善したい候補

- 入力画面を業務順に整理する
- 下書きと作成済みの違いを分かりやすくする
- 報告書、日報、請求の関係を見える化する
- マスタや設定を安全に編集できるようにする
- PDF生成エラー時に原因を分かりやすく表示する
- 実データとアプリ設定を分離する

## 確認が必要なこと

- 使う人は本人だけか、複数人か
- スマホ入力とPC入力のどちらが主か
- オフラインでも入力したいか
- 請求先は今後増えるか
- 完了報告書の形式は今の台紙を厳密に維持するか
- AppSheetと同じPDF生成方法を残すか
- 新アプリ公開先はVercelなどでよいか
