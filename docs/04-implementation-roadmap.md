# 実装ロードマップ

## Phase 0: 土台作り

- Git初期化
- README作成
- Drive調査結果の記録
- 技術方式の候補整理
- AppSheetアクセス方法の確認

完了条件:

- プロジェクトの目的と現在地がREADMEから分かる。
- GitHubに載せてよい情報と載せてはいけない情報が分かれている。

## Phase 1: 既存アプリの棚卸し

- AppSheetの画面一覧を確認
- AppSheetのアクションを確認
- AppSheetの自動化を確認
- AppSheetの式や仮想列を確認
- Googleテンプレートの使われ方を確認
- 既存UIの不便な点を洗い出す
- AppSheetの制約で諦めていたことを洗い出す
- 新アプリで追加・刷新したい機能候補を出す

完了条件:

- 引き継ぐ機能、作り直す機能、捨てる機能が分かれている。
- 新しく作りたい機能候補が整理されている。
- デザイン刷新で守るべき方向性が言語化されている。

## Phase 2: 要件定義

- 必須機能を決める
- 後回し機能を決める
- 入力項目を決める
- 画面一覧を決める
- 権限を決める
- PDF出力仕様を決める

完了条件:

- 最小実用版で何ができればよいか説明できる。

## Phase 3: 設計

- データ構造の設計
- 画面遷移の設計
- PDF生成方式の設計
- Google連携方式の設計
- エラー時の動きの設計

完了条件:

- 実装前に、どのデータがどこに保存されるか説明できる。

## Phase 4: 最小実用版

最初の実装候補:

- ホーム
- 完了報告書一覧
- 完了報告書作成
- 日報入力
- 月次まとめ表示
- 設定画面の一部

完了条件:

- サンプルデータで一通り画面を触れる。
- 本番Driveデータを壊さない。

## Phase 5: 帳票・PDF

- 完了報告書PDF
- 請求書PDF
- 月次作業金一覧PDF
- PDF保存先の管理

完了条件:

- 既存テンプレートと同等または改善された帳票が出せる。

## Phase 6: 運用準備

- バックアップ方針
- 権限管理
- エラー時の復旧手順
- 使い方メモ
- 本番移行手順

完了条件:

- 初心者でも更新・保守の入口が分かる。

## 毎回確認すること

- 今回の変更はどの業務を楽にするか
- 既存データを壊す可能性はないか
- 入力ミスを防げるか
- 将来、項目追加しやすいか
- 初心者が見ても意味が分かるか
