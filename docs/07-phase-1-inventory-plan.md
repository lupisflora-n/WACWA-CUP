# Phase 1: 既存アプリ棚卸し計画

## 目的

既存AppSheetアプリとDrive資産を調査し、新しい「オシゴトアプリ」で何を引き継ぎ、何を改善し、何を新しく作るかを決められる状態にする。

このPhaseでは、既存機能の再現だけを目的にしない。デザイン刷新と、AppSheetの制約を超える新機能の候補出しも同時に行う。

## Phase 1の完了条件

- 既存機能一覧がある
- 既存データと帳票テンプレートの対応関係が分かる
- 引き継ぐ機能、改善して作る機能、後回しにする機能、不要な機能が分類されている
- AppSheetの制約で困っていた可能性がある箇所を洗い出している
- 新アプリで追加したい機能候補がある
- デザイン刷新の方向性が言語化されている
- Phase 2の要件定義に進める確認事項がまとまっている

| --- | --- | --- |

## 調査対象

### 1. AppSheet

確認したいもの:

- 画面一覧
- フォーム項目
- 一覧画面
- 詳細画面
- アクション
- Automation
- Bot / Process / Task
- 式
- 仮想列
- Slice
- Security
- User settings

注意:

- AppSheetの管理画面は、Codexから直接読めない可能性がある。
- その場合は、ユーザー画面共有、スクリーンショット、または設定エクスポートで補う。

### 2. Google Sheets

確認したいもの:

- テーブル一覧
- 各列の意味
- IDと関連付け
- 計算列
- 空行や旧データ
- AppSheet用の補助列
- マスタデータ

### 3. Google Docs / Slides

確認したいもの:

- 完了報告書テンプレート
- 請求書テンプレート
- 月次作業金一覧テンプレート
- プレースホルダ
- PDF出力先
- 既存テンプレートを継続利用するか、新アプリ用に作り直すか

### 4. Driveフォルダ

確認したいもの:

- PDF保存先
- 画像保存先
- 請求書フォルダ
- 月報フォルダ
- 完了報告書フォルダ
- ファイル命名ルール

## 機能分類ルール

| 分類 | 意味 |
| --- | --- |
| 引き継ぐ | 既存と同等の機能が必要 |
| 改善して作る | 必要だが、画面や仕組みを変える |
| 新しく作る | AppSheetにはないが、新アプリで価値がある |
| 後回し | 将来必要だがMVPには入れない |
| 不要 | 新アプリでは作らない |

## 現時点の仮説

### 引き継ぐ可能性が高い

- 完了報告書作成
- PDF保存
- 駐車場領収書画像保存
- 日報入力
- 作業金、残業代、駐車場代、高速代の記録
- 溶剤・立替
- 月次請求まとめ
- 請求書PDF
- 月次作業金一覧PDF

### 改善して作る可能性が高い

- 入力フォーム
- 一覧検索
- PDF作成状態
- 月次まとめ画面
- 設定画面
- エラー表示
- スマホ操作

### 新しく作る候補

- ダッシュボード
- 今月の請求見込み
- 未PDF化・未確認の警告
- 入力漏れチェック
- 過去現場からの入力補助
- よく使う取引先・担当者の候補表示
- 月末処理チェックリスト
- PDF生成履歴
- テンプレート管理画面
- データバックアップ導線

## デザイン刷新の初期方針

- AppSheetらしい汎用画面から離れる
- 最初の画面は業務ダッシュボードにする
- スマホでは「今日入力する」「最近の報告書」「今月の請求」をすぐ触れるようにする
- PCでは一覧、検索、集計、確認を重視する
- 状態表示を明確にする
- 帳票アプリなので、派手さより信頼感と見通しを重視する
- ただし業務ツールとして冷たくなりすぎないよう、現場作業者が毎日使いやすい余白と操作感にする

## 次に行う調査

1. Drive内の現在のファイル構成を再確認する。
2. メインGoogle Sheetsのテーブル、列、サンプルデータを整理する。
3. 帳票テンプレートのプレースホルダを整理する。
4. AppSheet管理画面の確認方法を確定する。
5. 調査結果を機能分類表に落とし込む。
