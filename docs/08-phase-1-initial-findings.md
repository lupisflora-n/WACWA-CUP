# Phase 1 初回棚卸し結果

調査日: 2026-07-21

## 今回確認したこと

Google DriveとメインGoogle Sheetsを読み取り、既存AppSheetアプリの機能構造を推定した。

この調査では本番データやDriveファイルは変更していない。

## プロジェクト目的の再確認

このプロジェクトは、既存AppSheetアプリの単純移植ではない。

目的は次の通り。

- 既存の業務資産を活かす
- デザインを一新する
- AppSheetの制約を超えたオリジナルアプリにする
- 既存機能を改善する
- 新機能や機能刷新を検討する
- 管理、更新、保守しやすい形にする

## デザイン刷新の方向性

初期方針:

- AppSheetの汎用的な見た目から離れる
- スマホでは現場入力を最短にする
- PCでは検索、確認、集計を重視する
- 状態表示を強くする
- 帳票や請求を扱うため、信頼感と視認性を優先する
- ただし毎日使う道具なので、硬すぎず、入力しやすい画面にする

画面の初期候補:

| 画面 | 目的 |
| --- | --- |
| ホーム | 今日の作業、未処理、今月の請求状況 |
| 完了報告書一覧 | 検索、状態確認、PDF確認 |
| 完了報告書フォーム | 現場情報、作業内容、費用、画像 |
| 日報入力 | 作業金、残業、駐車場、高速 |
| 経費/溶剤入力 | 溶剤、立替、マイナス請求 |
| 月次まとめ | 月ごとの集計、請求書作成 |
| 帳票/PDF管理 | PDF生成履歴、再生成 |
| 設定 | 作業者、取引先、単価、保存先 |

## 現時点のリスク

| リスク | 内容 | 対応 |
| --- | --- | --- |
| AppSheet設定未確認 | 画面、アクション、Automation、式の詳細がまだ不明 | AppSheet管理画面の確認が必要 |
| 本番データ混在 | 現在のSheetsには本番情報が含まれる | 開発時はコピーまたはサンプルデータを使う |
| 帳票生成方式不明 | AppSheetテンプレとSlides置換が混在している可能性 | テンプレート単位で整理する |
| データ構造がAppSheet寄り | 空行、補助列、Slice用の考え方が混ざっている | 新アプリ用のデータモデルに再設計する |
| 個人情報/現場情報 | GitHubに載せてはいけない情報が多い | 実ID、住所、個人情報はコミットしない |

推奨:

- DriveとSheetsだけでは、既存アプリの操作体験や自動化処理が確定できない
