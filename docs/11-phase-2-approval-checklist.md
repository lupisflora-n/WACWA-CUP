# Phase 2 Approval Checklist

Date: 2026-07-22
Status: Waiting for user approval

## 目的

このチェックリストは、実装に入る前に決めるべきことを短くまとめたものです。

ここでの「承認」とは、完璧に全仕様を決めることではありません。次の作業に進んでも大きく手戻りしない程度に、方向性を決めることです。

## 承認してほしい推奨方針

### 1. アプリ形態

推奨: Webアプリ + PWA対応

意味:

- ブラウザで使えるアプリとして作る。
- スマホのホーム画面にも置けるようにする。
- 最初からApp Store/Google Play配布は狙わない。

承認欄:

- [ ] OK
- [ ] 変更したい

### 2. ログイン

推奨: Googleログイン

意味:

- 今のGoogle Drive/Sheets資産と相性がよい。
- 誰が使ったかを記録しやすい。

承認欄:

- [ ] OK
- [ ] 変更したい

### 3. 最初のプロトタイプ範囲

推奨: 完了報告中心

最初に作るもの:

- ホーム画面
- 完了報告一覧
- 完了報告詳細
- 新規報告作成
- 下書き保存
- PDF作成ジョブの状態表示

最初は後回しにするもの:

- 請求書の完全自動生成
- 月次一覧表の完全自動生成
- 高度な権限管理
- オフライン対応

承認欄:

- [ ] OK
- [ ] 変更したい

### 4. PDF/請求書生成の扱い

推奨: 画面とデータの土台を作った後に本実装

意味:

- 先にアプリの骨組みを作る。
- PDF生成は「ジョブ」として状態管理できるように設計しておく。
- 実際のPDF出力は後続フェーズで安定して実装する。

承認欄:

- [ ] OK
- [ ] 変更したい

### 5. PDF保存先

推奨: Google Drive継続

意味:

- 既存運用を大きく壊さない。
- 生成PDFへのリンク管理を新アプリ側で整理する。

承認欄:

- [ ] OK
- [ ] 変更したい

### 6. 初期権限

推奨: 最初は2種類

- 管理者
- 一般ユーザー

意味:

- 最初から細かく分けすぎない。
- 必要が分かった段階で、事務担当・現場担当・閲覧者などを追加する。

承認欄:

- [ ] OK
- [ ] 変更したい

## 承認後に進む作業

上記が承認されたら、次は以下を作成します。

1. 画面設計書
2. データ設計書
3. PDFジョブ設計書
4. 技術スタック決定書
5. MVP実装タスク一覧

## ユーザーへの回答依頼

次に進む場合は、以下のように回答してください。

`1-6すべてOK`

または、変更したい番号だけ指定してください。

例:

`3だけ変更したい。最初から請求書も入れたい。`
