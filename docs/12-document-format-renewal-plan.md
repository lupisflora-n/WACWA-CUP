# Document Format Renewal Plan

Date: 2026-07-22
Status: New requirement

## 背景

Phase 2の確認中に、PDF生成の扱いについて重要な変更が出ました。

当初案では、PDF/請求書の完全実装は後続フェーズに回す予定でした。

ただし、次の2種類の書類は初期段階からPDF作成可能にする必要があります。

- 工事完了報告書
- 丸産報告書

また、この2種類の書類は新しい書式に変更されました。

ユーザーは新しい書式のPDFとExcelデータを受け取っています。これを確認し、最終的にはアプリ上のフォームから入力できるようにする必要があります。

## 方針変更

Phase 2の承認事項4は、以下に変更します。

旧:

- PDF/請求書の完全実装は、画面とデータの土台ができた後でよい。

新:

- 工事完了報告書と丸産報告書は、初期MVPでPDF作成可能にする。
- 請求書、月次一覧表、その他のPDFは後続フェーズでよい。
- 新しい書式PDF/Excelを解析して、アプリフォーム項目に変換する。

## 目的

目的は、書式そのものを眺めて終わることではありません。

最終目的は、ユーザーがアプリ上で迷わず入力でき、その入力内容から新しい書式のPDFを作れる状態にすることです。

つまり、必要な作業は以下です。

1. 新しいPDF書式を確認する
2. 新しいExcelデータを確認する
3. PDFとExcelのどこが入力項目かを洗い出す
4. 既存AppSheet/Sheetsの項目と対応づける
5. 足りない項目、不要になった項目、名前が変わった項目を整理する
6. アプリ上のフォーム項目案を作る
7. ユーザーに入力項目を確認してもらう
8. 承認後、フォームとPDF生成の実装へ進む

## 対象書類

### 1. 工事完了報告書

必要な確認:

- PDF上の見た目
- Excel上のセル構造
- 入力が必要な項目
- 自動計算できる項目
- 固定文言として持てる項目
- 写真や添付欄の有無
- 既存データから引き継げる項目

### 2. 丸産報告書

必要な確認:

- PDF上の見た目
- Excel上のセル構造
- 入力が必要な項目
- 自動計算できる項目
- 固定文言として持てる項目
- 写真や添付欄の有無
- 既存データから引き継げる項目

## 分析時の分類

新しい書式を確認したら、各項目を以下のように分類します。

- ユーザーが毎回入力する項目
  - 例: 日付、現場名、作業内容など。
- マスタから選ぶ項目
  - 例: 作業者、溶剤、単価、請求先など。
- 自動入力できる項目
  - 例: 作成日、ログインユーザー、連番など。
- 計算で出せる項目
  - 例: 金額、小計、合計など。
- 固定表示でよい項目
  - 例: 会社名、定型文、タイトルなど。
- PDFには必要だがアプリ入力画面には出さない項目
  - 例: 内部ID、ファイル名、管理番号など。
- 既存AppSheetにはあるが新書式では不要な項目
- 新書式にはあるが既存AppSheetにはない項目

## 成果物

新しいPDF/Excelを確認した後、次の資料を作成します。

- 書式別項目一覧
- アプリフォーム項目案
- 既存データとの対応表
- 不足項目・追加項目リスト
- PDF生成に必要な差し込み項目一覧
- ユーザー承認用チェックリスト

## 注意点

実装前に、入力項目は必ずユーザー確認を通します。

理由:

- PDF書式の見た目だけでは、どこまで入力すべきか判断できない場合がある。
- Excelには計算式や隠しセルがある可能性がある。
- アプリでは入力しない方がよい項目もある。
- 入力項目を間違えると、後からデータ修正が大変になる。

このため、新しい書式を見た後すぐ実装せず、まず項目確認表を作ります。
