# 新書式の項目分析

調査日: 2026-07-22

状態: 原本分析完了、ユーザー確認待ち

## 調査範囲

受領したPDFとExcelを読み取り専用で確認した。

- PDF: ページ数、用紙、見た目、欄の配置
- Excel: シート構成、使用範囲、セル値、数式、画像
- 既存Google Sheets: 見出し行と、項目の意味を確かめるための最小限の既存レコード

原本ファイルは変更していない。実データ、メールアドレス、住所、個人名はGitHubに保存しない。

## 最初に確認が必要なこと

ファイル名と書類の中身が、次のように交差している。

| ファイル名 | 実際に確認できた内容 |
| --- | --- |
| `完了報告書.xlsx` | 工事完了報告書 |
| `丸産報告書.pdf` | 工事完了報告書 |
| `丸産報告書.xlsx` | 丸産向けの作業日報 |
| `完了報告書.pdf` | 丸産ロゴ付きの作業日報 |

内容から見ると、PDFのファイル名だけが入れ替わっている可能性が高い。実装では内容を基準に仮分類しているが、確定にはユーザー確認が必要。

## 書式全体の確認結果

- PDFはどちらもA4縦、1ページ。
- PDF自体に入力フォーム機能はない。
- Excelテンプレートに計算式は入っていない。
- 工事完了報告書Excelは1シート。
- 丸産Excelは3シート。
  - 作業日報
  - 提出方法と記入方法の説明
  - 工事担当者、部門、メールアドレスの一覧
- 丸産Excelの担当者一覧は、将来の選択候補マスタとして利用できる。ただしメールアドレスは秘密情報としてGitHubに置かない。

## 工事完了報告書

| 書式上の欄 | 新アプリでの扱い | 既存データ | 判定 |
| --- | --- | --- | --- |
| 宛先会社 | 候補選択または手入力 | `toCompany` | 引き継げる |
| 宛先事業所 | 候補選択または手入力 | `toOffice` | 引き継げる |
| 宛先担当者 | 候補選択または手入力 | `toPerson` | 引き継げる |
| 作業者 | ログイン利用者から初期入力、変更可能 | `workerName` | 引き継げる |
| 1回目・2回目・3回目 | 1つを選択 | `attemptCount` | 引き継げる |
| 完了・未完 | 1つを選択 | `completionStatus` | 引き継げる |
| 応援 | 複数人を選択 | `supporters` | 引き継げる |
| 駐車場代 | 金額入力 | `parkingFee` | 引き継げる |
| 高速代 | 往復などの入力から自動集計 | `tollType`, `tollOneWay`, `tollGo`, `tollReturn` | 改良して引き継ぐ |
| 材料代 | 金額入力 | `materialFee` | 引き継げる |
| 日付 | 日付入力 | `workDate` | 引き継げる |
| 現場名 | 候補選択または手入力 | `siteName` | 引き継げる |
| 注文No | 文字入力 | `orderNo` | 引き継げる |
| 住所 | 過去現場から候補表示、手入力可能 | `address` | 引き継げる |
| 工事内容 | 3件の明細入力 | `work2` から `work10` | 構造変更が必要 |
| 数量 | 各工事内容に対する数値または文字 | なし | 新規追加 |
| 備考 | 各工事内容に対する文字入力 | なし | 新規追加 |
| 作業時間 | 開始・終了または時間数 | なし | 新規追加 |
| 吹付塗装の有無 | 有・無の選択 | なし | 新規追加 |

| 通常材料以外の材料内容 | 使用時に必須の文字入力 | なし | 新規追加 |
| お客様のために取り組んだこと・現場日誌 | 複数行入力 | `diary1` | 引き継げる |
| 合計 | 金額入力または計算 | `constructionTotal` | 計算規則の確認が必要 |
| 消費税 | 自動計算を推奨 | `tax` | 計算規則の確認が必要 |
| 合計額 | 合計と税から自動計算 | なし | 新規の計算表示 |

### 推奨フォーム構成

1. 宛先
2. 現場情報
3. 作業結果
4. 工事明細3件
5. 作業時間と施工条件
6. 経費
7. 現場日誌
8. 金額確認
9. 下書き保存または完了してPDF作成

### データ設計上の重要点

既存の `work2` から `work10` は、内容だけを横に並べた構造になっている。新書式では工事内容、数量、備考が1組なので、新アプリでは「工事明細」という子データにする。

1明細は次の3項目を持つ。

- 工事内容
- 数量
- 備考

これにより、後で書式が変わっても列を増やし続けずに管理できる。

## 丸産報告書（作業日報）

### フォーム項目案

| 書式上の欄 | 新アプリでの扱い | 既存データ | 判定 |
| --- | --- | --- | --- |
| 工事担当名 | 担当者マスタから選択 | `ms_personInCharge` | 引き継げる |
| 提出日 | PDF作成日を初期値にする | なし | 新規追加 |
| 作業日 | 日付入力 | `ms_date` と `workDate` | 重複を統合する |
| 現場名及び工事内容 | 文字入力 | `ms_site` | 名称変更して引き継ぐ |
| AM時刻 | 時刻入力 | `ms_am_time` | 引き継げる |
| PM時刻 | 時刻入力 | `ms_pm_time` | 引き継げる |
| AM作業内容 | 複数行入力 | `ms_work2` から `ms_work4` | AM/PM分離が必要 |
| PM作業内容 | 複数行入力 | 明確な専用列なし | 新規追加 |
| 作業員名1から6 | 利用者・作業者マスタから選択、手入力可 | `ms_nameL1` から `ms_nameR3` | 引き継げる |
| 連絡事項・注意事項・明日の作業予定 | 複数行入力 | 明確な専用列なし | 新規追加 |
| 社名 | 会社設定から自動入力、変更権限は管理者のみ | なし | 新規追加 |

### 推奨フォーム構成

1. 提出先と日付
2. 現場情報
3. AMの時刻と作業内容
4. PMの時刻と作業内容
5. 作業員
6. 連絡事項・注意事項・明日の予定
7. 内容確認
8. 下書き保存または完了してPDF作成

### 担当者マスタ

丸産Excelには、工事担当者、部門、メールアドレスの一覧がある。

新アプリでは次のように扱うことを推奨する。

- 工事担当者名を選択肢として表示する。
- 部門を保持し、担当者の絞り込みに使えるようにする。
- メールアドレスはサーバー側だけで保管し、一般利用者の画面には原則表示しない。
- マスタの更新日を記録する。
- 将来、PDFを担当者へ送信する機能を追加できる形にする。

## 推奨データ構造

保守しやすくするため、1つの巨大な表に全項目を追加し続けない。

| データ | 役割 |
| --- | --- |
| `reports` | 両書式に共通するID、種類、状態、作成者、更新日時、PDF状態 |
| `completion_report_details` | 工事完了報告書だけの宛先、現場、費用、施工条件、合計 |
| `completion_work_items` | 工事内容、数量、備考の明細 |
| `marusan_report_details` | 丸産だけの担当者、提出日、AM/PM、連絡事項、社名 |
| `report_workers` | 作業員一覧と表示順 |
| `construction_managers` | 丸産の担当者、部門、連絡先マスタ |
| `pdf_jobs` | PDF作成の進行中、成功、失敗、再実行 |

この分け方なら、画面や書式を変えても影響範囲を限定しやすい。

## 実装前に確定が必要な点

1. PDF2ファイルの名前が入れ替わっているという理解で正しいか。
2. 工事完了報告書の工事明細は3件固定でよいか。
3. 工事完了報告書の合計、消費税、合計額をどう計算するか。
4. 駐車場代、高速代、材料代を合計欄へ含めるか。
5. 丸産のAM/PM欄は、それぞれ時刻と作業内容を入力する理解で正しいか。
6. 丸産の「社名」に毎回表示する正式名称は何か。
7. 丸産の連絡事項、注意事項、明日の作業予定は1つの欄でよいか、3つに分けるか。

回答は `docs/15-form-field-approval-checklist.md` の選択肢に沿って確認する。
