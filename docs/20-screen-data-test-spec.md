## 2. 画面遷移

```text
S01 Login
  -> S02 Home
     -> S03 Document type
        -> S05 Completion form
        -> S06 Marusan form
     -> S04 Draft list -> S05 or S06
S05/S06 -> S07 Receipt edit (optional)
        -> S08 Confirmation
        -> Save draft -> S04
        -> Confirm complete -> S09 PDF job
S09 -> S10 Completed PDF
    -> Retry -> S09
S02 -> S11 Admin settings -> S12 Layout adjustment
```

戻る操作では入力内容を保持する。完了確定後は一般利用者が帳票内容を変更できない。訂正は新しい改訂として扱う。

## 3. 入力項目と保存先

### 完了報告書

| 項目 | 入力 | 保存 | ルール |
| --- | --- | --- | --- |
| 宛先会社、部署、担当 | テキスト | reports | 必須条件を設定 |
| 作業日、現場、注文番号、住所 | 日付/テキスト | reports | 日付形式を検証 |
| 工事内容 | 複数行 | report_itemsまたはreports | Enter改行を保持 |
| 数量 | なし | 固定値 | 先頭行のみ「一式」 |
| 備考 | なし | 空欄 | 入力不可 |
| 合計 | 数値 | reports | 駐車場・高速・材料を含めない |
| 消費税 | 数値 | reports | 合計×10%、切り捨て。上書き可 |
| 吹付 | 有/無 | reports | PDFで選択項目に丸印 |
| 吹付詳細 | 複数行 | reports | 吹付「有」の場合に表示 |
| 通常材料以外 | 複数行 | reports | 常時表示 |
| 領収書 | 画像 | attachments | 元画像と加工画像を分離 |
| 完了状態 | 選択 | reports | 完了/未完をPDFへ反映 |

### 丸産報告書

| 項目 | 入力 | 保存 | ルール |
| --- | --- | --- | --- |
| 担当者 | テキスト | reports | 権限に応じて編集 |
| 作業日 | 年/月/日数値 | reports | 西暦、範囲検証 |
| 現場 | テキスト | reports | 必須 |
| AM/PM | 自由入力 | report_items | 各欄を保持 |
| 作業内容 | 6欄 | report_items | AM3欄、PM3欄 |
| 作業者 | 6欄 | report_items | 先頭欄は本人を固定可能 |
| 会社名 | なし | company_settings | 株式会社ＴＲＣ固定 |
| 備考等 | 複数行 | reports | 改行と自動折り返し |

## 4. エラー表示

| 状況 | 利用者への表示 | データの扱い |
| --- | --- | --- |
| 必須未入力 | 「未入力の項目があります」+項目名 | 保存は下書きのみ可 |
| 数値不正 | 「数字で入力してください」 | 不正値を保存しない |
| 日付不正 | 「正しい日付を入力してください」 | PDF作成不可 |
| 枠に収まらない | 「文字量が枠を超えています」+項目名 | PDFを保存しない |
| 画像読み込み失敗 | 「画像を読み込めません」 | 元データを保持、再選択可 |
| PDF作成失敗 | 「PDFを作成できませんでした」+ID | 入力を保持、再試行可 |
| Drive保存失敗 | 「保存できませんでした」 | 完成扱いにしない |
| 権限不足 | 「この操作は管理者のみ可能です」 | 操作を拒否、記録 |
| 二重実行 | 「処理中です」 | 新しいジョブを作らない |

## 5. テストケース

### 基本操作

- Googleログイン後にホームが表示される。
- 完了報告書を新規作成し、下書き保存、再開、完了確定ができる。
- 丸産報告書を新規作成し、6欄の内容と6名の作業者が保存される。
- 戻る、再読み込み、再ログイン後も保存済み内容が残る。

### PDF

- 工事内容の任意改行がPDFでも改行される。
- 任意改行がない長文は枠幅で折り返される。
- 枠高を超える場合、欠けたPDFが完成扱いにならない。
- 消費税が10%で計算され、1円未満が切り捨てられる。
- 消費税の手動上書きがPDFへ反映される。
- 吹付の有/無の丸印が正しい位置に描画される。
- 領収書が指定枠に収まり、加工画像が出力される。
- PDF作成失敗後に再試行できる。

### 安定性と権限

- PDF作成ボタンを連打しても重複ジョブ・重複PDFが生じない。
- 通信切断後に入力データが消えない。
- 一般利用者が他人の下書きを編集できない。
- 管理者だけがレイアウトとマスタを変更できる。
- 直前のレイアウト設定へ戻せる。

## 6. 承認ゲート

| ゲート | 承認対象 | 承認後に進める作業 |
| --- | --- | --- |
| G1 | 画面一覧、遷移、入力項目 | UIプロトタイプ |
| G2 | データ移行方針、保存構造 | データ層と認証 |
| G3 | PDF方式、配置設定、領収書加工 | PDF試作 |
| G4 | サンプル検証結果 | 本番接続準備 |
| G5 | 本番公開手順、復旧手順 | 限定公開 |

現時点ではG1からG3の設計案を提示している段階で、実装開始の承認はまだ取得していない。

## 7. 実装単位

1. 開発用サンプルデータと認証
2. ホーム、書類一覧、下書き
3. 完了報告書入力
4. 丸産報告書入力
5. 領収書編集
6. PDF直接描画と配置設定
7. PDFジョブ、Drive保存、再試行
8. 管理設定と権限
9. テスト、限定公開、運用手順

各単位は、コード、テスト、変更記録を一つのGitHub履歴として管理する。
