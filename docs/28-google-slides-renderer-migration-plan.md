# Google Slides + Apps Script 生成経路への移行方針

更新日: 2026-07-24

## 結論

PDFの描画一致を最優先するため、新アプリのPDF生成主経路は、現行と同じ次の流れにする。

`新アプリフォーム → Google Sheets/連携API → Apps Script → Google Slides台紙を複製 → タグ置換・画像配置 → PDF化 → Google Drive保存`

ブラウザのHTML印刷は、通信できない場合の確認用または開発用に残す。会社提出用PDFはGoogle Slides経路で作成する。

## 現行資産として確認できたもの

- 現行GAS仕様書: Drive上の `SPEC_工事完了報告書_v2.0_FIX`
- 完了報告書のSlides台紙ID: `1X6ouLZBV56-Mz8XmdnR0kSC63gJnsTPegmTK_gmfRUU`
- PDF保存先フォルダID: `1S_je5bOw_KWBcgYeKbpjKWD3551T83Jl`
- 現行GASは `replaceAllText` でタグを置換する。
- `{{parkingReceiptImg}}` はタグ図形の位置・大きさを読み取り、画像を同じ枠へ挿入する。
- `完了/未完`、`1回目/2回目/3回目` は `〇` 用の専用タグへ置換する。
- 応援者はカンマ区切りを `、` へ整形して出力する。
- 一時Slidesを複製し、PDF作成後に一時ファイルを処理する。

## 新アプリ側の責任

新アプリは次を担当する。

1. 現行と同じフォーム項目を入力する。
2. 下書き、作成依頼中、作成済み、完了、履歴を保存する。
3. フォーム値を、GASが読む列名・JSON項目へ変換する。
4. 領収書画像をDriveへ保存し、画像IDまたはURLを渡す。
5. PDF生成依頼を発行する。
6. GASが返したPDFのID・URL・状態を表示する。
7. 新規項目、タグ、位置、文字サイズを設定データとして管理する。

## GAS側の責任

GASは次を担当する。

1. 認証済みの依頼だけを受け付ける。
2. 指定された書式のSlides台紙を複製する。
3. 既存タグを現行と同じルールで置換する。
4. 丸印タグを現行と同じ位置・大きさで置換する。
5. 領収書をタグ図形の枠へ配置する。
6. SlidesをPDFへ変換し、Driveへ保存する。
7. 同名ファイルの重複を避ける。
8. 成功・失敗・再試行結果をデータへ書き戻す。

## 新台紙への対応

完了報告書と丸産報告書は、別々のSlides台紙ID・タグ台帳・配置定義を持つ。

- 完了報告書のタグを丸産報告書へ流用しない。
- 既存タグは現行名を優先して保持する。
- 新規項目は新台紙のタイトルを初期項目名にする。
- タグ文字列は項目名と分離し、設定画面から変更できるようにする。
- 配置値はGASコードへ直接埋め込まず、設定シートまたは設定JSONから読み込む。

## 〇と応援者の扱い

〇は画面上の文字を丸で囲む処理を新しく発明するのではなく、現行GASの専用タグ置換を優先して移行する。これにより、現行の丸印の位置・大きさ・フォントを再利用できる。

応援者はフォームの選択結果を現行と同じ区切り文字へ整形して、既存の応援者タグへ渡す。新台紙で表示位置を変える場合だけ、丸産用と完了報告書用の配置設定を別々に変更する。

## 未確認のため、推測で実装しないもの

- 新アプリから呼び出す正式なGAS WebアプリURLと認証方式。
- 現行GASが現在も本番で稼働しているか。
- 丸産報告書用の現行GAS関数・Slides台紙ID。
- 新台紙へ追加するタグの正式な文字列一覧。
- PDF生成後に利用者へ共有する権限ルール。

これらは、GASプロジェクトの閲覧権限または正式なWebアプリURLが確認できた後に確定する。

## 移行の合格テスト

同じ入力データについて、次を比較する。

1. 現行GASが作成したPDF。
2. 新アプリが同じGAS経路で作成したPDF。
3. ページ数、A4サイズ、文字、丸印、応援者、金額、改行、領収書画像の位置・大きさ。

この比較で一致を確認するまで、移行完了とは扱わない。
