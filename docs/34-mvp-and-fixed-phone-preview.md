# オシゴトアプリ MVP と固定スマホプレビュー

更新日: 2026-07-25

## 目的

現行AppSheetの構造と帳票資産を引き継ぎながら、スマホで入力しやすい新アプリを先に触れる状態にする。修正しやすさを優先し、入力画面、帳票台紙、タグ、配置、PDF連携を分けて管理する。

## MVPでできること

- 工事完了報告書の入力
- 丸産報告書の入力
- 入力途中の下書き保存と再編集
- 必須項目・金額・日付の入力検証
- 領収書画像の追加、トリミング、白黒化、回転、複数枚管理
- 正式台紙に入力値を重ねたプレビュー
- 印刷ダイアログからPDF保存
- 完了記録とPDF処理一覧
- 帳票の編集、削除、再試行
- タグ名とタグ配置の画面編集
- JSONバックアップの書き出し・読み込み
- 既存のGoogle Slides台紙を使うPDF生成経路

## 固定URL

通常確認:

<https://lupisflora-n.github.io/WACWA-CUP/>

台紙だけを確認する場合:

- 工事完了報告書: <https://lupisflora-n.github.io/WACWA-CUP/?fixture=completion-reference>
- 丸産報告書: <https://lupisflora-n.github.io/WACWA-CUP/?fixture=marusan-reference>

スマホでは通常確認URLを一度開き、ブラウザの「ホーム画面に追加」またはブックマークを使う。URLはリポジトリの公開先が変わらない限り同じである。Wi-Fiは不要で、携帯回線で確認できる。

## 更新の仕組み

`main`に公開対象の変更を反映すると、`.github/workflows/deploy-pages.yml` が次を実行する。

1. `npm ci`
2. `npm run build`
3. `dist/404.html` を含む公開ファイルをGitHub Pagesへ配置
4. 固定URLへ反映

`404.html` はGitHub Pagesで直接開いた補助URLでもアプリの入口を表示するためのSPAフォールバックである。

## 現時点の制限

- サンプル環境の標準保存先はブラウザの端末内保存である。
- 端末を変えた場合、同じデータは自動では見えない。必要に応じて設定画面からバックアップを移す。
- Google Drive / Sheets共有保存は、Googleログイン、許可メール、Apps Scriptの権限を設定してから受入する。
- Google Slides PDFの公開Webアプリは、認証・許可メール・実データを使った最終確認が済むまで本番運用とみなさない。
- 月報、請求関連、複数人の本番権限管理はMVP後の段階である。

## 受入確認の順番

1. 固定URLをスマホで開く。
2. 工事完了報告書を新規作成し、途中で保存する。
3. 下書きから再編集し、必須項目と金額を入力する。
4. 必要なら領収書画像を追加・加工する。
5. プレビューで台紙、文字位置、入力値を確認する。
6. 丸産報告書も同じ順番で確認する。
7. PDF保存、完了記録、再編集、削除を確認する。
8. 期待と違う箇所は「画面」「入力項目」「タグ名」「タグ配置」「PDF連携」のどこを直すか分けて修正する。
